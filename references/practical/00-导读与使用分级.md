# 实用沟通与网络社交策略：导读与使用分级

## 定位

把本目录当作 composition patterns、话术素材和训练骨架，不当作 Action Selector 或保证有效的心理学定律。回复类先由 `../personal/回复决策与对话流.md` 选择唯一 Primary Action，本目录只能在已选动作内提供实现；最终由 `../personal/自然回复生成器.md` 输出首选。优先级固定为 `CORE_POLICY → canonical personal references → Decision Layer → practical realization`；冲突时 practical 必须退让，不得绕过边界、ownership、Current Action、stop condition 或 Decision Sufficiency，也不得建立新的主策略 taxonomy。

`Architecture Marker: PRACTICAL_COMPOSITION_GATING_V1`。本目录中的“回应、共情、分享、提问、转题、调侃、邀约”等都只是 component labels。成品只能使用 Decision Layer 已选的 Primary Action 与显式许可的 supporting functions；模板顺序、示例、反馈、冷场、好素材和训练目标都不产生 permission。`ASK / TOPIC_SHIFT / INVITE / PLAY` 必须逐项获准；`WAIT` 不输出消息，`LEAVE_SPACE / CLOSE` 不附 question、hook、invite 或 topic extension。候选先做 same-action repair，仍冲突则拒绝并返回 Decision Layer。

不要机械照抄。先确认事实、双方关系和用户日常口吻，再把句式改写得自然。若用户提供聊天截图或原话，优先贴合其用词长度、标点和亲密程度。

## 使用分级

### A：可直接作为建议框架

- 识别并承认情绪可作为 `EMPATHIZE` realization；只有 `Primary Action = ASK` 或 supporting `ASK` 获准时，才询问对方需要倾听、陪伴还是建议。
- 冲突中聚焦具体行为和当下问题，避免人格攻击、翻旧账和情绪勒索。
- 赞美保持具体、真实，并说明对方的行为带来的积极影响。
- 拒绝时表达清晰边界，不把委婉变成含糊承诺。
- 提供支持的同时保留双方自主性，不把情绪价值理解为单方面讨好。
- 道歉采用“承认影响 + 简短解释 + 补救动作”，不要用长篇自辩稀释责任。

### B：策略性使用

#### 万能句库

把现成句子当成用户临时不会表达时的脚手架。简单回复只选一个最合适的骨架并改成用户口吻；用户明确要求多个或存在真正策略分支时才展示多个。对“我完全懂你”“永远”“一定”等绝对承诺，先确认用户是否真的愿意承担。

#### 茶艺、撒娇与示弱

用于暧昧、调情、降低对抗、给对方表现空间或表达“我在意你”。适合双方都享受这种互动且不存在重大利益决定的场景。若长期隐藏真实意见，可能形成讨好、失去主动权或让对方误判需求。

常用结构：

- 轻微示弱 + 对方可完成的小请求；
- 具体肯定 + 一点俏皮夸张；
- 表达失落但不指责 + 给对方修复入口；
- 已选动作内可使用顺势承接组件；见面或具体行动组件仅在 `Primary Action = INVITE` 时启用，不由撒娇／示弱模板自动追加。

#### 留白、节奏与适度推拉

通过不过度解释、把一部分安排交给对方、在一次清晰邀约后停止本轮追加，观察对方是否主动投入。未明确拒绝且后来出现新时间或活动信息，只能形成“未来仍允许一次低成本现实验证”的 relationship-level permission；届时是否选择 `INVITE` 仍由 Decision Layer 重新判断。两次代表性邀约都没有替代安排且持续缺乏投入时，形成降低投入的 constraint，而不在本节直接选择当前 turn action。把留白用于筛选互惠，不用于制造恐慌、嫉妒、依赖或故意冷淡。

#### 顺从式回应

可短期用于哄人、调情或结束无意义争执。不要用于金钱、性同意、婚姻、生育、健康、长期边界或其他重大决定。

#### 迟到与失误解释

优先给真实版本：“简短说明 + 道歉 + 补救”。若用户明确想使用经过包装或编造的理由，说明它的短期过关作用以及被追问、穿帮和损害信任的风险；不要替用户编造会伤害他人、规避重大责任或造成财产人身风险的事实。

#### 主动权与气场

把主动权理解为：清楚表达、给出选择、设定时间窗口、不过度追问、根据反馈调整投入。不要把强势写成羞辱、威胁、冷暴力或故意贬低。

### C：高风险慎用或拒绝协助

- 贬低、威胁、冒充身份、散布隐私、持续纠缠、跟踪或报复；
- 以酒精、药物、压力、权力差或欺骗绕过同意；
- 为骗取金钱、婚姻、生育或性关系而隐瞒重大事实；
- 制造极端嫉妒、孤立对方或系统性煤气灯操控。

指出其现实风险，并提供达到合法合理目标的低风险替代方案。

## 给用户方案的格式

简单“怎么回”默认给一个可发送的首选，最多一句必要理由。不要自动附关系分析、完整分支或让用户在三种风格间重新做决定。

用户明确要求多个版本或确有不同策略分支时，可以从以下维度生成真正有差异的版本，并先说明更推荐哪个：

1. **稳健版**：真实、自然、长期风险低。
2. **会撩版／策略版**：更有情绪张力，使用幽默、留白、撒娇、顺势肯定或节奏控制。
3. **强势版**：强调边界、主动权和快速筛选。

只有发送时机、代价或后续分支会改变当前决策时才补充；简单任务不为模板完整而展开。serious 场景优先准确承接和边界，不默认调用“会撩版”。
