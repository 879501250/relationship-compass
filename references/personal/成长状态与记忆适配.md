# 成长状态与记忆适配

## 原则

记忆只在用户首次明确同意后启用，服务于减少重复和支持成长。使用 `scripts/memory_store.py`，写入独立的 `relationship-compass` 命名空间，不读取或覆盖 upstream 数据库。

不保存完整聊天、截图、导出、账号、地址或私密影像。用户可查看、暂停、恢复、撤销、忘记对象、撤回同意或清空。

## 启用

```bash
python scripts/memory_store.py status
python scripts/memory_store.py enable --confirm
```

只有用户明确同意后运行 enable。拒绝不影响当前任务。脚本失败时说明没有持久化。

## 五类 scope

| scope | 内容 | 来源 |
| --- | --- | --- |
| `user` | current/target、用户确认的 growth/autonomy、稳定目标和边界 | 仅 `user_explicit` |
| `object` | 对象代号和用户明确提供的稳定事实/边界 | 用户明确陈述或转述 |
| `relationship` | 当前对象明确确认的关系状态、现实约束和直接表达的边界 | 用户明确陈述或转述 |
| `event` | 邀约、兑现、冲突、修复、关系变化和用户主动报告的训练实践 | 用户叙述或工具证据摘要 |
| `hypothesis` | stage/trend/humor receptivity、interview mode、技巧熟练度、画像更新建议 | 必须带证据、置信度、对象和生命周期 |

事实、推测、建议和未知的分类遵循 `../../shared/FACT_HYPOTHESIS_POLICY.md`；时间与 TTL 遵循 `memory_lifecycle.md`。`stage_estimate`、`trend_estimate` 和 `humor_receptivity` 不得写入 confirmed scope。

## 回复生成时的 scope 语义

- **user scope** 属于用户本人。已确认的稳定事实、表达偏好和边界可跨对象复用，但只在当前任务相关时召回；换对象不等于忘记用户自己的风格。
- **object scope** 属于一个特定对象。对方偏好、边界、过去行为、幽默或调侃接受度必须匹配当前 `subject_id`，不得从对象 A 迁移给对象 B。
- **relationship scope** 属于“用户 + 特定对象”的配对。已确认的关系状态、现实约束、双方边界和配对历史只用于对应关系；其他对象不能继承。`stage_estimate`、`trend_estimate`、互动模式解释等仍按 hypothesis 使用，不能仅因与该配对相关就升级为事实。

相关性是所有 scope 的共同门槛。存在 Memory 不代表应写进回复；不召回无关 user fact，也不加载其他对象或配对的信息补足当前未知。

`event` 写入必须提供带时区的 ISO 8601 `occurred_at`，并区分：

- `landmark`：第一次见面、关系确认、明确分开、重大修复等长期节点；
- `normal`：后续判断仍可能需要的一般关键事件；
- `temporary`：短期观察点，最先进入淘汰候选。

`occurred_at` 是实际发生时间，`updated_at` 是本地写入/更新时间。时间线按 `occurred_at`，补录旧事不会因为今天写入就伪装成最近事件。landmark 不因普通 event FIFO 上限自动删除；上下文优先 landmark，再取最近 normal/temporary。

## 用户共享状态

以下放在 `scope=user, subject_id=user`，可以跨对象共享：

- `current_style`：用户确认的当前表达摘要；
- `target_style`：用户明确选择的目标表达；
- `growth_state`：当前训练焦点和 continuation ownership 摘要；
- `autonomy_state`：A0/A1/A2；
- `capability_profile`：分维度的长期能力画像；
- `comfortable_techniques`、`preferred_flavor`、`avoid_styles`、稳定边界。

表达能力可以共享；不能把某个对象的接受度写进 user scope。

E1–E5 只描述单条消息的内部表达路由，不写成全局稳定等级。旧 `trained_expression_level` 仅视为 legacy，不再新增或拿来概括全部能力。

## capability_profile

只使用以下维度：`initiative`、`self_disclosure`、`opinion`、`storytelling`、`observation_humor`、`callback`、`teasing`、`flirting`、`continuation`。

每项只能是：

- `emerging`：偶尔能做到，但仍明显依赖协助；
- `developing`：多次做到，稳定性或跨场景迁移仍有限；
- `stable`：在多种合适场景中能自然认领并接续。

不制造百分制、总分或“综合 E3.4”。模型观察先写 hypothesis；只有用户确认后，才以 `scope=user, subject_id=user, source_type=user_explicit` 写入稳定 `capability_profile`。

## 对象隔离状态

以下必须使用当前对象 `subject_id`：

- 关系阶段、走势和现实约束；
- 对方明确边界；
- 对方是否接受某类幽默或暧昧；
- 近期技巧使用和重复风险；
- 与该对象的关键事件与假设。

对象 A 的接梗、反调侃、E4 接受度或 callback 不能迁移给对象 B。召回使用：

```bash
python scripts/memory_store.py context --subject-id obj-a --max-chars 4000
```

该命令只返回 user 共享状态与 obj-a 的记录。

`context` 必须提供 `--subject-id`，绝不支持省略对象后的全量上下文。需要审计全部内容时使用 `show`；`show` 仍允许省略对象。

近期技巧通过对象字段 `recent_techniques` 保存最近 8 次实际发送的主技巧。只有用户确认发送后才记录：

```bash
python scripts/memory_store.py record-technique --subject-id obj-a --technique callback --confirm-sent
```

AI 只提出过但用户没有发送的版本不进入技巧历史。用户通用熟练度放进 capability profile，对象技巧历史不得共享。

## current_style 更新与过期

`current_style` 带脚本 `updated_at` 和派生 `review_status`。旧记录进入复核/过期后不得继续充当能力上限。

流程：

1. 近期多段证据持续与旧画像冲突；
2. 模型只写 `hypothesis: style_update_suggestion` 或在当前任务提出建议；
3. 向用户说明观察到的变化和旧值；
4. 用户确认后以 `source_type=user_explicit` 更新 `current_style`；
5. 用户未确认时不改稳定字段。

查看状态：

```bash
python scripts/memory_store.py style-status
```

到期只表示需要复核，不自动断言用户退步或进步。

## autonomy_state

- `A0`：AI 可完整给首选；
- `A1`：优先保留用户草稿，只做局部优化；
- `A2`：默认用户先写，AI 只校准一个关键点。

不机械升级。模型观察只能作为 hypothesis；用户确认后更新稳定字段。状态可按实时场景临时切换而不写入长期记忆。

## 写入示例

```bash
python scripts/memory_store.py apply --json '{"scope":"user","subject_id":"user","field":"target_style","value":"主动分享、观点、小故事、适度调侃；避免油腻和霸总","source_type":"user_explicit","source_ref":"turn:confirmed","confidence":"high"}'
```

```bash
python scripts/memory_store.py apply --json '{"scope":"hypothesis","subject_id":"user","field":"style_update_suggestion","value":"近期多段对话已能稳定先分享再提问，建议复核 current_style","source_type":"assistant_inference","source_ref":"turn:review","confidence":"medium"}'
```

自动更新后只显示一行摘要和撤销方式。没有高价值变化不写；模型不得把 partner response 当作 user growth 事实。

landmark 事件示例：

```bash
python scripts/memory_store.py apply --json '{"scope":"event","subject_id":"obj-a","field":"first_meeting","value":"第一次线下见面","source_type":"user_report","source_ref":"turn:confirmed","occurred_at":"2026-08-01T19:00:00+08:00","retention":"landmark","confidence":"high"}'
```

## Review Mode 与实际发送学习

每 1–2 周或关键节点复盘时，读取 `复盘模式与实际发送学习闭环.md`。复盘必须分开 User Growth 与 Partner / Relationship，最后只选一个训练重点。

AI 建议不等于实际发送。用户主动提供实际发送版本时，比较差异、提取用户愿意认领的表达偏好；不以对方反馈直接判定哪个版本更优秀。`current_style`、`preferred_flavor` 或 capability profile 仍须用户确认后更新。

## 控制命令

- `show [--subject-id]`
- `context --subject-id <id> [--max-chars 4000]`
- `undo [--op-id]`
- `delete --scope <scope> --subject-id <id> --field <field> [--occurred-at <ISO>] --confirm`
- `record-technique --subject-id <id> --technique <name> --confirm-sent`
- `pause` / `resume`
- `forget-object <id> --confirm`
- `revoke --confirm`
- `revoke --delete --confirm`
- `clear --confirm`
